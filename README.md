# Motion Trace 動作軌跡分析

上傳一段投擲影片(飛鏢、棒球、羽球…皆可),自動追蹤手腕、手肘、肩膀、食指的移動軌跡,可慢動作播放、匯出疊圖影片,並用 Gemini 產生白話的「教練式」修改建議。

整個工具是**單一 `index.html`**,全部在瀏覽器本機運算,**影片不會上傳**。

## 功能

- 姿勢追蹤(MediaPipe Pose + Hand):骨架/軀幹、手腕、手肘、肩膀、食指軌跡,各自可開關
- 軌跡長度:最近 0.5 / 1 / 2 秒(越舊越淡),或從頭累積到目前
- 網格、參考線、0.25× / 0.5× / 1× 播放
- 匯出疊圖影片(依所選速度錄製)
- 去抖與離群點剔除(平滑強度可調)、骨長合理性過濾(追蹤過濾:嚴格 / 寬鬆 / 關閉)
- 拍攝品質提醒(偵測率低、人物太靠邊、太小、投擲手被擋住…)
- Gemini 教練建議:白話、不用專業術語、附對應的練習方式

## 快速開始

```bash
cd motion-trace
python3 -m http.server 8000
```

瀏覽器開 `http://localhost:8000`(請用 http,不要直接開檔案)。手機可在同一個 Wi-Fi 開 `http://<電腦 IP>:8000`。

1. **載入影片**:選擇檔案。頁面會自動偵測影片實際幀率。
2. **設定**:選「投擲手」(左/右)、「辨識精度」(預設高精度)、「取樣頻率」(預設自動)。
3. **開始分析**:會顯示進度與預估剩餘時間。第一次要下載姿勢模型(高精度約 30MB)。
4. **檢視結果**:播放、拖曳進度條、切換各種軌跡與顯示選項。
5. **Gemini 建議**(選用):貼上自己的 API Key、選模型,按「產生分析與建議」。

## 設定說明

| 設定 | 說明 |
|---|---|
| 投擲手 | 選錯會追到另一隻手。背對/側面拍攝時兩邊都試一下,看哪邊的線貼著伸出去的手臂 |
| 辨識精度 | 高精度較準、較慢(首次下載約 30MB);標準較快(約 9MB) |
| 取樣頻率 | 預設自動 = 影片實際幀率。選得比實際高會自動降回實際值(只會重複分析同一幀) |
| 平滑強度 | 0 = 原始資料;越大越平順,太大會磨平真實的快速動作 |
| 追蹤過濾 | **嚴格**:線乾淨,但手被擋住時中斷。**寬鬆**:手被擋住時也盡量畫手腕,但會抖。**關閉**:不過濾 |
| 軌跡長度 | 長影片含多次投擲,建議用「最近 1 秒」;全部疊在一起會很雜 |

## Gemini API Key

- Key **只存在頁面記憶體**,不寫入 localStorage / cookie,重新整理就消失。
- Key 只會直接送到 Google(`generativelanguage.googleapis.com`),不經過其他伺服器。
- 填入後可按「載入可用模型」,下拉選單會改成你帳號實際能用的 Gemini 模型。
- 會送出的內容:6 張關鍵幀(已疊骨架與軌跡)與估算的量化數據。

## 怎麼拍效果最好

- **側面或斜後方 45 度**,不要正後方;投擲手那側不要被身體擋住
- **全身入鏡、人物置中、不要貼邊**,人物盡量佔畫面高度一半以上
- 鏡頭固定、光線充足、背景單純
- 想追得準:用手機的**慢動作模式**(120 / 240 fps)拍

## 已知限制

- 手被頭或身體擋住時(例如飛鏢回拉階段),姿勢模型本身看不到,追蹤會中斷或不準;這是模型與拍攝角度的限制
- 食指在高速出手瞬間很不穩
- 「估計出手時間」是用手腕速度峰值推測,不是真正偵測放手瞬間
- 影片含多次投擲時,指標是整段混在一起算,尚未支援「逐次投擲」分析
- 匯出疊圖影片時分頁要留在前景;Safari 的錄影格式支援未驗證
- AI 建議僅供參考

## 技術

- 純前端:HTML + CSS + 原生 JS(ES module),無 build、無後端
- [MediaPipe Tasks Vision](https://developers.google.com/mediapipe)(`@mediapipe/tasks-vision` 0.10.14,CDN 載入)
- Canvas 2D 繪圖、`MediaRecorder` 匯出
- Google Gemini API(`generateContent`,使用者自帶 key)
